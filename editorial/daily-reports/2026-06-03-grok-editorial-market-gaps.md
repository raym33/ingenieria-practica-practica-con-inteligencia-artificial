# Informe editorial — Qué piden lectores técnicos a recursos de IA aplicada

Fecha: 2026-06-03

Fuente: análisis aportado por Grok sobre señales de X de 2025-2026 relacionadas con frustraciones y deseos de developers, founders, consultores y empresas.

## Lectura editorial

La señal es muy consistente: el lector no quiere otro recurso de prompts, ni otra demo, ni una lista de herramientas.

Quiere aprender a diseñar sistemas completos.

Los huecos repetidos:

- demasiada teoría sin producción;
- tutorials aleatorios sin profundidad;
- foco excesivo en el modelo;
- poca arquitectura completa;
- poco código ejecutable;
- pocos diagramas de workflows reales;
- poca explicación práctica de cómo funciona el modelo por debajo;
- poca cobertura de costes, latencia, fiabilidad, observabilidad y guardrails;
- falta de roadmaps con proyectos reales.

## Decisión editorial

El libro debe presentarse explícitamente como:

> Un manual para construir sistemas de IA completos, no demos.

Eso implica que cada parte debe conectar:

- fundamento;
- arquitectura;
- implementación;
- evaluación;
- operación;
- coste;
- riesgo;
- aprendizaje continuo.

## Cambios recomendados

1. Reforzar introducción con lo que el libro promete y lo que no promete.
2. Reforzar roadmap con el ciclo completo: trigger, contexto, decisión, tools, validación, humano, feedback.
3. Añadir una ruta de lectura para entender el motor de los LLMs sin quedarse en teoría.
4. Añadir checklist editorial de "sistema completo".

## Riesgo editorial

El riesgo no es que falten capítulos.

El riesgo es que el lector no vea una columna vertebral clara.

La columna vertebral debe ser:

```text
problema -> contexto -> modelo -> acción -> evaluación -> operación -> coste -> mejora
```
